# Potholes Detection System - Main Copilot Instructions

## Project Overview
This is a comprehensive pothole detection and management system built with a modular architecture. The system collects data, processes it using computer vision and ML, stores results, and provides visualization interfaces.

## Technology Stack
- **All Backend Modules**: C# with .NET 9 (including AI/ML processing)
- **Database**: MongoDB for document storage and spatial indexing
- **Frontend**: Angular with TypeScript
- **API Communication**: REST APIs between modules
- **Machine Learning**: ML.NET and ONNX.NET for AI/ML processing

## Module Structure
The project consists of four main modules, each with their own specialized Copilot instructions:

1. **[data-collection/](./data-collection/.copilot-instructions.md)** - Data collection from devices and sensors (C# .NET 9)
2. **[detection-analysis/](./detection-analysis/.copilot-instructions.md)** - Computer vision and ML processing (C# .NET 9)
3. **[database-storage/](./database-storage/.copilot-instructions.md)** - Data persistence and management (C# .NET 9 + MongoDB)
4. **[reporting-visualization/](./reporting-visualization/.copilot-instructions.md)** - User interfaces and analytics (Angular + .NET 9)

### Common Patterns

#### C# .NET 9 Pattern Example (Data Collection, Database, Web API)
```csharp
// Consistent error handling pattern
public async Task<Result<T>> ExecuteOperationAsync<T>(Func<Task<T>> operation)
{
    try
    {
        var result = await operation();
        _logger.LogInformation("Operation completed successfully: {ResultId}", result.Id);
        return Result.Success(result);
    }
    catch (SpecificException ex)
    {
        _logger.LogError(ex, "Specific error occurred: {Message}", ex.Message);
        return Result.Failure<T>(ex.Message);
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "Unexpected error: {Message}", ex.Message);
        return Result.Failure<T>($"Operation failed: {ex.Message}");
    }
}

// Consistent logging pattern
private readonly ILogger<ServiceName> _logger;

// Dependency injection pattern
public class ServiceName
{
    private readonly IRepository _repository;
    private readonly ILogger<ServiceName> _logger;
    
    public ServiceName(IRepository repository, ILogger<ServiceName> logger)
    {
        _repository = repository;
        _logger = logger;
    }
}
```

#### C# .NET 9 ML Pattern Example (AI/ML Module)
```csharp
// ML.NET pattern for model inference
public class MLModelService
{
    private readonly MLContext _mlContext;
    private readonly ITransformer _model;
    private readonly ILogger<MLModelService> _logger;
    
    public MLModelService(ITransformer model, ILogger<MLModelService> logger)
    {
        _mlContext = new MLContext(seed: 0);
        _model = model;
        _logger = logger;
    }
    
    public async Task<Result<PredictionResult>> PredictAsync<TInput, TOutput>(TInput input)
        where TInput : class
        where TOutput : class, new()
    {
        try
        {
            var predictionEngine = _mlContext.Model.CreatePredictionEngine<TInput, TOutput>(_model);
            var prediction = predictionEngine.Predict(input);
            
            _logger.LogInformation("ML prediction completed successfully");
            return Result.Success(new PredictionResult { Data = prediction });
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "ML prediction failed");
            return Result.Failure<PredictionResult>($"Prediction failed: {ex.Message}");
        }
    }
}
```

### Testing Guidelines

#### C# .NET 9 (All Modules including AI/ML)
- Use xUnit or NUnit as the testing framework
- Use Moq for mocking dependencies
- Implement integration tests with TestContainers for MongoDB
- For ML testing, use ML.NET test frameworks and synthetic data
- Aim for high test coverage (>85%)
- Use FluentAssertions for readable assertions
- Aim for high test coverage (>90%)

#### Angular (Frontend)
- Use Jasmine and Karma for unit testing
- Use Cypress or Playwright for e2e testing
- Use Angular Testing Utilities for component testing

### Dependencies Management

#### .NET Dependencies
- Use NuGet packages with PackageReference
- Use Directory.Packages.props for centralized package management
- Pin package versions for reproducibility

#### Angular Dependencies
- Use npm or yarn for package management
- Use package-lock.json for version locking
- Regularly update dependencies for security

## Inter-Module Communication
- Use RESTful APIs for synchronous communication between modules
- Implement proper data validation at module boundaries
- Use message queues (RabbitMQ/Azure Service Bus) for async processing
- Handle module failures gracefully with circuit breaker patterns
- Use OpenAPI/Swagger for API documentation

## Performance Considerations
- Implement caching with Redis for frequently accessed data
- Use batch processing for large datasets
- Monitor memory usage, especially for image processing in Python
- Optimize MongoDB queries with proper indexing (2dsphere for geo queries)
- Consider horizontal scaling for high-load scenarios
- Use CDN for static assets in Angular app

## Security Guidelines
- Validate all input data (use Data Annotations in .NET, Joi in Angular)
- Use HTTPS for all communications
- Implement JWT authentication and authorization
- Store sensitive data securely (Azure Key Vault recommended)
- Regular security audits and dependency updates
- Use OWASP guidelines for web security
