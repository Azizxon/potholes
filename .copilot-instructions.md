# Potholes Detection System - Main Copilot Instructions

## Project Overview
This is a comprehensive pothole detection and management system built with a modular architecture. The system collects data, processes it using computer vision and ML, stores results, and provides visualization interfaces.

## Module Structure
The project consists of four main modules, each with their own specialized Copilot instructions:

1. **[data-collection/](./data-collection/.copilot-instructions.md)** - Data collection from devices and sensors
2. **[detection-analysis/](./detection-analysis/.copilot-instructions.md)** - Computer vision and ML processing
3. **[database-storage/](./database-storage/.copilot-instructions.md)** - Data persistence and management
4. **[reporting-visualization/](./reporting-visualization/.copilot-instructions.md)** - User interfaces and analytics

## Global Coding Standards

### Code Style
- Use consistent naming conventions across all modules
- Prefer descriptive variable and function names
- Add comprehensive docstrings for all public functions
- Use type hints consistently
- Follow PEP 8 for Python code

### Architecture Principles
- Maintain clear separation of concerns between modules
- Use dependency injection for better testability
- Implement proper error handling and logging
- Design for scalability and performance
- Follow async/await patterns for I/O operations

### Common Patterns
```python
# Consistent error handling pattern
async def operation_with_error_handling():
    try:
        result = await some_async_operation()
        logger.info(f"Operation completed successfully: {result.id}")
        return result
    except SpecificException as e:
        logger.error(f"Specific error occurred: {e}")
        raise
    except Exception as e:
        logger.error(f"Unexpected error: {e}")
        raise OperationError(f"Operation failed: {e}")

# Consistent logging pattern
import logging
logger = logging.getLogger(__name__)

# Consistent configuration pattern
from dataclasses import dataclass
from typing import Optional

@dataclass
class ModuleConfig:
    setting1: str
    setting2: int
    optional_setting: Optional[str] = None
```

### Testing Guidelines
- Write unit tests for all modules
- Use pytest as the testing framework
- Mock external dependencies and services
- Aim for high test coverage (>90%)
- Include integration tests for module interactions

### Dependencies Management
- Use requirements.txt for Python dependencies
- Pin dependency versions for reproducibility
- Regularly update dependencies for security
- Document any system-level dependencies

## Inter-Module Communication
- Use well-defined interfaces between modules
- Implement proper data validation at module boundaries
- Use async queues for data pipeline processing
- Handle module failures gracefully

## Performance Considerations
- Implement caching where appropriate
- Use batch processing for large datasets
- Monitor memory usage, especially for image processing
- Optimize database queries with proper indexing
- Consider horizontal scaling for high-load scenarios

## Security Guidelines
- Validate all input data
- Use secure communication protocols
- Implement proper authentication and authorization
- Store sensitive data securely
- Regular security audits and updates
